## 一页纸

**这张表是什么**：借据上发生的每一笔豁免，把「线上按余额成分豁免」和「线下豁免还款」两类合在一张表里。

**一行是什么**：线下豁免是一笔交易一行；线上豁免是一笔交易的某一个余额成分一行，同一个交易流水号会有多行。粒度按 `waiver_seq`，来源为推断，**不能保证唯一**。两类的序号来自两张不同源表的自增主键，合并后没有去重。 ⚠ 两类序号可能撞号

**更新与取数**：每天跑一次，每个分区是当期的**增量**。取某一天的豁免用 dt = 那一天；取一段时间把这段的 dt 分区合起来。

**收哪些数据**：

- 线上豁免：当天的减免明细里记录状态正常的。（规则 r1）
- 线下豁免：当天交易主表里交易场景为线下豁免还款的。（规则 r2）
- 两类都要能在产品表里找到产品，否则整行不进表。（规则 r3） ⚠ 产品表没有按生效日期过滤

**数据从哪来**：

| 上游表 | 在本表的作用 |
| --- | --- |
| `demo_ods.ods_loan_waiver_detail_di`（合并分支） | 线上豁免的主表：余额成分、豁免类型、豁免金额 |
| `demo_ods.ods_loan_trade_main_di`（合并分支） | 线下豁免的主表；线上豁免的状态与时间补充 |
| `demo_ods.ods_loan_account_df`（补充字段） | 线下豁免的客户号与借据号补充 |
| `demo_ods.ods_product_main_df`（过滤） | 只留能找到产品的交易 ⚠ 关联时没有按生效日期过滤，同一产品有多个版本时一笔会变多行 |

**谁在用**：下游任务 `ads_collection_waiver_daily`（写 `demo_ads.ads_collection_waiver_1d`）。

**适合用来**：统计每天的豁免笔数与金额；查某个借据被豁免的记录
**不适合**：看豁免申请与审批过程；按豁免类型统计线下豁免：线下没有豁免类型

**要注意**：

- 「豁免类型」两套码值说法打架：表注释是字母码，SQL 注释是数字码；实际存哪套待确认。（矛盾）
- 「借据号」两类来源不同：线上取借据号，线下取贷款账号。（矛盾）
- 与产品表关联时没有按生效日期过滤，可能一笔变多行。（风险）
- 只覆盖老核心；新核心的豁免不在这张表里。（覆盖）

## 加工过程

**产出任务**：`dwd_collection_fee_waiver_daily`（每天）：每天把线上、线下两类豁免合成一张豁免明细，给催收的豁免统计使用。

1. 线上：减免明细（当天、状态正常）左关联交易主表（按交易流水号），内关联产品表（按产品编码）。
2. 线下：交易主表（当天、场景为线下豁免还款）左关联贷款账户（按合同号），内关联产品表。
3. 两类上下拼接（不去重），写入当天分区。
