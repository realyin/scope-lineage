### S10g 构建与渲染（顺序不能变）

**目的**：构建 `ontology.json`，渲染互链的表语义页和概念页。

**命令**

```bash
rm -rf "$RUN/onto" "$PAGES"
sl catalog build "$RUN/merged" --out "$RUN/onto" --lineage "$RUN/artifacts" --tables "$RUN/corpus/tables.json"; echo "exit=$?"
sl semantic render "$RUN/docs" --out "$SEMPAGES" --validation "$RUN/validation.json" --ontology "$RUN/onto/ontology.json" --packets "$RUN/packets"; echo "exit=$?"
sl catalog render "$RUN/onto/ontology.json" --out "$PAGES" --semantics "$SEMPAGES"; echo "exit=$?"
load_tables
sl semantic status "$RUN" --pages "$SEMPAGES" --only "${TABLES[@]}"
python3 "$SKILL/scripts/catalog_check.py" "$RUN/onto/ontology.json" \
  --digest "$RUN/digest/digest.json" --changes "$RUN/catalog_changes.md" > "$RUN/catalog_check.txt"; echo "exit=$?"
cat "$RUN/catalog_check.txt"
```

顺序：`build` → `semantic render --ontology` → `catalog render --semantics`。`build` 固定带 `--lineage` 和 `--tables`（页面上的证据靠它们）。

最后一条是**漏做检查**。`catalog validate` 和合并的覆盖率只查「写错」，查不出「漏做」；目录起草者能力弱一些时，漏做最常见。
`catalog_check.py` 读构建出的 `ontology.json`（带 `--digest` 时也读 `digest.json` 的规则，带 `--changes` 时读 `catalog_changes.md` 的 skip 行），列出这几类：

| 发现 | 意思 | 谁来补 |
| --- | --- | --- |
| `empty_concept` | 概念一个属性都没有 | T5 返工：给概念建属性。本批没有它自己的表、也没有它的名称 / 描述列时，在 `catalog_changes.md` 写 `<概念 id> empty skip: <理由>`（有自己的表的概念，这一行不算数） |
| `missing_participant` | 事件表里有外键列指向某个概念，它却不在事件的参与者里 | T5 返工：补参与者 |
| `attribute_beside_foreign_identifier` | 名称 / 描述列（`*_desc`、`*_name`、`*_nm`）绑成了本表概念的属性，同表同词根的编码列却指向另一个概念 | T5 返工在那个概念上建属性，再 T6 返工改绑成 `foreign_attribute` |
| `unabsorbed_rule` | digest 里某张表 `filter` / `dedup` / `derive` 规则 `<库.表>#rN` 没有约束在 `rules` 里引用，`catalog_changes.md` 也没写 skip | T5 返工：写约束（`rules` 指回它），或在 `catalog_changes.md` 写 `<库.表>#rN skip: <理由>` |
| `state_without_states` | 状态属性有码值集，概念却没有它的 `states` | T5 返工：在概念上写 `states`（取值照 digest） |
| `measure_without_unit` | 度量属性没有 `unit` | 属性是 T5 建的 T5 返工，片段建的 T6 返工：补 `unit` 和 `additivity` |
| `metric_incomplete` | 指标缺 `unit` 或 `additivity`，或 `sum` / `avg` / `min` / `max` 缺 `measure` | T5 返工：补齐；缺 `measure` 的，在 `on` 概念上建度量属性再指向它 |
| `code_attribute_without_relation` | 名字像编码 / 键的列（`*_cd`、`*_id`、`*_no`、`*_code`）绑成了普通属性、属性又没有码值集 | 指向另一个概念的，照那一行发现写的做：本表的概念是事件时，T5 返工把那个概念列为事件的参与者（没有标识符就先建；参与关系自动派生，不手写），是实体时 T5 返工在 `relations` 里建关系；然后 T6 返工把这一列改绑 `foreign_identifier`。只是本概念自己的编号、或材料证明不了它指向那个概念：在 `catalog_changes.md` 写一行 `<库.表.列> code skip: <理由>`（别的写法脚本不认，那一条会一直报） |

每条发现是「要看一眼」，不等于一定错。

**产出与自检**：`Built ontology-json/3 from catalog …`（下一行 `evidence:` 的「N of M relation(s) backed by a JOIN」只是证据统计，小样里是 0 也不用处理；`build` 报的关系数比 `catalog validate` 的多是正常的：每个事件参与者会派生一条参与关系，`validate` 只数目录里手写的）；`Rendered N table page(s) and index.md (skipped=0)`；
`Rendered N page(s) (C concept page(s)) -> …`；`$PAGES/concepts/`、`$PAGES/index.md`、`$SEMPAGES/<表>.md` 都在；`status` 全部 `rendered`。

**常见失败与处理**

| 现象（原文） | 退出码 | 处理 |
| --- | --- | --- |
| `--semantics directory does not exist: …` | 2 | 顺序错了：先跑 `semantic render` 再跑 `catalog render` |
| `build` 有 error、什么也没写 | 1 | 回 S10f 修 `merged/`，或交 owner |
| render 打印 `warning: packet_stale …` / `invalid …` / `no_packet …` | 0 | 回 S8 |
| `catalog_check.txt` 末行不是 `0 finding(s)` | 1 | 逐条决定：要补的，用 `fill catalog … REWORK=@"$RUN/catalog_check.txt"` 让 T5 返工（`MODE` 与 S10c 那次相同：新建或增量）（只补概念属性、参与者、states、约束、关系和 skip 行），T5 改了绑定相关的概念或属性时再 `fill fragment … MODE=返工 REWORK=@"$RUN/catalog_check.txt"` 让 T6 改绑（T5 只加了 skip 行就不用）；然后依次重做 S10d 的自检、S10e 合并（先 `rm -rf "$RUN/merged"`）、S10f、S10g。返工最多 2 次。不补的，在 `catalog_changes.md` 每条写一行理由 |

**完成判据**：三条命令都 `exit=0`；`status` 全部 `rendered`；`catalog_check.txt` 末行是 `0 finding(s)`：不补的每一条都按上表的格式在 `catalog_changes.md` 写了 skip 行（`empty skip` / `states skip` / `#rN skip` / `code skip`）再重跑。没有 skip 写法的类别（`missing_participant` 等）不补时，在 `catalog_changes.md` 写理由，并在 `RESULT.md` 列出。
`catalog validate` 仍报 `state_attribute_without_states` 而 `catalog_changes.md` 里有那个概念的 `states skip` 行时，是正常的：validate 不读这个文件，以 `catalog_check` 为准，不算返工失败。

**已知限制**（遇到时照做，不要去修工具）：

| 情况 | 怎么做 |
| --- | --- |
| 码值来自 SQL 内联字典（`VALUES` 列表、`CASE` 映射、`INLINE(ARRAY(STRUCT))`）；digest 不列出它们，关联条件也不会去筛这类常量表的行 | 片段里对照表语义（必要时读 SQL）写码值集的 `values`，`evidence` 写任务名，不写 `lookup` |
| 不带字符串常量的关联、拉链表的有效期列 | digest 不列出。按表语义和 `catalog-fragment-prompt.md` 的码值规则写 |
| 列注释与血缘矛盾（注释说是 A，SQL 取的是 B） | 以血缘为准，写进 `notes` 和待确认问题 |
