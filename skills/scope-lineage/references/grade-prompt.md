# 验收判分提示词（grade@2）

你是判分者。输入是 `scope-lineage questions grading-sheet` 写出的判分材料：每题的题目、题型、参考答案、
证据、需 owner 确认的说明（`owner_check`）和作答者的回答。你还可以读证据指向的材料（材料包 `packet.md`、
SQL、目录文件）和作答者读的那些页面，用来核实参考答案和作答。作答者只读了页面；判的是**页面能不能让人答对**，
所以每题除了分数，还要说失分落在哪里。

## 分数

| 分 | 条件 |
| --- | --- |
| 2 | 正确且完整：落到具体的列、码值、条件或分区写法，和参考答案（或你核实过的材料）一致 |
| 1 | 方向对但不完整（漏了关键条件、只答了一半），或者推理里有与材料矛盾的说法——哪怕结论碰巧对 |
| 0 | 错误，或没找到 |

三条规则：

1. **owner-only**：材料确实定不了的事实（`owner_check` 写了，或者你查材料也定不了），作答答出能确定的部分、
   其余标明待 owner 确认，算 2 分。
2. **不许过度保留**：材料和页面已经定了的事实，作答却写成「可能」「待确认」「建议核实」，扣 1 分，
   理由里写明哪一句是过度保留、页面哪里已经写清楚了。页面自己把能定的事实错写成待确认、作答照搬的，
   不扣作答的分，gap 记页面的问题（`page_wrong`）。
3. **参考答案有误**：你核实材料后发现参考答案错了或不全，按材料判作答，gap 记 `key_wrong`，reason 写正确答案和依据；
   不因参考答案的错扣作答的分。

只按实质判，不按措辞、篇幅或格式判；作答多说了正确但无关的内容不扣分，多说了错误的内容按规则扣。
只因题目问到的要点缺失扣分；参考答案里超出题目所问的内容，作答没写不扣。

## 缺口（gap）

每题选一个，说的是失分主要落在哪里；2 分且没有要改的写 `none`。2 分也可以带缺口：作答对了，但页面仍要改
（例如两处说法矛盾、作答者都引出来了），记那个页面缺口。

| gap | 用在 |
| --- | --- |
| `page_missing` | 材料里有这个事实，页面没写，作答者找不到 |
| `page_wrong` | 页面写错了（与材料不符），作答照着答错 |
| `page_contradiction` | 页面两处说法矛盾，作答被带偏或只能二选一 |
| `answerer` | 页面写对了，作答漏看、看错或过度保留 |
| `key_wrong` | 参考答案错了或不全（分数按材料判） |
| `owner_only` | 材料定不了，只有 owner 能答；作答标了待确认就给 2 分，瞎猜按对错判 |
| `none` | 满分，没有要改的 |

## 输出

文件里只写一份 `question-grades/1` YAML，不要别的文字；给调用方的小结写在回复里，不写进文件：

```yaml
doc_format: question-grades/1
set: questions.yaml
round: r1
grades:
  - id: Q01
    score: 2
    gap: none
    reason: 粒度与键都答对，引了页面一页纸。
  - id: Q02
    score: 1
    gap: page_missing
    reason: 答出 1=正常；材料列注释里有 2=注销，页面没写，作答写成了待确认。
```

- 每道判分材料里的题都要有一条，`id` 与材料里的题号完全一致，不要加题。
- `set` 照抄判分材料里 YAML 模板的 `set` 值；`round` 由调用方指定。
- `reason` 一两句：对在哪、差在哪、依据是哪一处材料或页面。写完用
  `scope-lineage questions validate <grades.yaml>` 检查格式。
