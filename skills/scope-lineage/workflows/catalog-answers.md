### "按这个问题写 SQL / 这个数怎么取 / 这张表、这个字段是什么" — 用目录回答业务问题

有人维护的本体目录（`catalog-yaml/1`，已 `catalog build` 出 `ontology.json`）时，业务问题先问目录，不要从 SQL 重新推。
命令里 `<O>` 是 `ontology.json`，`<S>` 是表语义 JSON 所在目录（没有就去掉 `--semantics <S>`），`<P>` 是待确认记录文件
（用户没指定就用 `ontology.json` 旁边的 `pending.jsonl`）。四个命令的完整说明在 `docs/zh-CN/ontology-catalog.md` 的
「检索」「取数包」「SQL 检查」「待确认的定义」四节。

**先分题。** 每类都先跑第 1 步的 `search` 拿到 id。不写 SQL 的题，答案第一句就是直接答案（问"会不会""要不要"的，第一个字是
"会 / 不会 / 要 / 不要"，定不了就说"定不了"及原因），再写依据和待确认；第 7 步的格式只用于写了 SQL 的题。

| 问题 | 做法 |
| --- | --- |
| X 取哪些值、是什么意思 | `context --table <表> --columns <列> --brief --focus`，读每列全文的「码值」「含义」「注意」；属性另跑 `catalog query <O> attribute <id>`。只问"是什么"的照 `references/catalog-questions.md` |
| X 改了会影响什么 | `catalog query <O> identifier <id>`（落在哪些列）和 `carriers <概念>`（带它的表）；对每张表跑 `context --table <表> --brief`，列出「下游」的每一项（写明个数），读由 X 加工出的列的全文「加工」。有语料产物时再照 `workflows/impact.md` 查到列级的下游（概念级见 `workflows/concept-impact.md` 末段） |
| 行会不会重复、要不要去重 | `context --table <表> --columns <键列> --brief --focus`：读「粒度」「证据与目录矛盾」「一行是」（唯一：…）和点名键列的「注意」「待确认问题」；要给去重写法时接着做第 3–7 步 |
| 统计、取数、某个数怎么算 | 下面 1–7 步，不跳步 |

两条对所有题都成立：
- 说"目录没写""没核对"之前，先读那一列的全文（`--column`）：格式、码值、由哪几列加工，常写在那里。写了就照用，不说"请核实"。
- 材料没说的事不下结论（两张表会不会重复记同一件事、某列为空表示什么）：说"材料没说"，需要时按第 4 步留占位。

**1. 检索：从问题到候选。**

```bash
scope-lineage catalog search <O> "<问题原文>" --semantics <S>
```

- 从候选里挑出问题点到的每样东西：要数或要算的（概念、`[指标]`）、按什么分或筛（属性、码值集）、在哪张表（每条的 `在：`）。
  按 id 挑；候选只是候选，排第一的不一定对。
- 同名的属性落在不同概念上（`在：` 不同）：取问题点名的那个概念的，答案里说另几个属于哪个概念、为什么没取；问题的说法同时
  覆盖几个概念，就每个都答。
- 要的东西不在列表里，依次各试一次：(a) 只用问题里的业务名词再搜（去掉时间、数量、动词）；(b) 加 `--kind`
  （`concept`、`metric`、`attribute`、`identifier`、`code_set`、`table`，可重复）只看那一类；(c) `catalog render <O> --out <pages>`
  后读 `index.md`，按域找概念。三次都找不到（`search` 退出码 1 也算一次）：它目录里没有，按第 4 步留占位，不要拿近似名代替。

**2. 取数包：所有表一次 `context`。**

还不知道列名时，先看每张表的列清单（每个绑定列一行：列名、指向的属性或标识、码值集，几 KB）：

```bash
scope-lineage catalog query <O> table <库.表>
```

再把 SQL 要碰的每一列（选出的、条件里的、关联的、分组的、去重的、聚合的）带上跑一次包。一张表：

```bash
scope-lineage catalog context <O> --semantics <S> --table <库.表> --columns <列,列,...> --brief --focus
```

两张及以上的表写进**同一次**调用（`--columns` 只认一张表，所以列改用 `--column 库.表.列`，每列一个）：

```bash
scope-lineage catalog context <O> --semantics <S> --table <库.表A> --table <库.表B> \
  --column <库.表A.列> --column <库.表B.列> --brief --focus
```

输出末尾每对表有一节 `# 关联 A ↔ B`：关联用「骨架的 ON 用这一对」的列对；每侧写着「每个关联键一行」还是「对上多行」，后者对另一侧的列
SUM / COUNT 会重复计数；「要过滤」列出的列必须进条件；写「分区…写入批次」「目录没记录」的分区不是过滤条件（见第 3 步第 2 条）；
SQL 骨架照抄后再改。这一节写「目录没有支持这两张表直接关联的列对」时，不要自己找列来连：有「一跳的桥」就把桥表加进 `--table`
重跑这一次调用（只重跑一次）；没有桥就按第 4 步留占位。

第 1 步挑到了 `[指标]`（它的 `在：` 是概念），或表包「目录」里列出了概念上的指标名而问题要算的正是它，再跑一次读「指标」一节：

```bash
scope-lineage catalog context <O> --concept <概念 id>
```

包里必须读完的：每张表的「目录」（粒度、时间形态、分区怎么读、范围、约束、证据与目录矛盾）、「怎么读」（一行是什么、取数、范围）、
「不适用」、「注意」、「待确认问题」，以及每个请求字段的全文。输出长就重定向到文件分段读完，不要只读开头。包里写「本表没有表语义文档」
时，只有目录事实可依，答案里说这张表的读法和注意"没人写下来"。只在还缺某一列的说明时补跑 `--column`，不要逐列跑。
不读 `ontology.json` 全文，不读概念页和表语义页（第 1 步的 `index.md` 除外）。

**3. 写 SQL。**

1. 每个条件、关联、去重、日期列都在包里找到依据（哪张表的哪一节、规则号 `r?`、约束 id），写进答案。包里定了的照写，
   不加"可能""建议核实"，也不给它加占位。
2. 日期列按「目录」里「分区」那一行：
   - 「每个分区一份全量，只取一个分区」：WHERE 写一个分区，不跨分区相加。
   - 「写入批次，不是事件日期」：时段按它点名的事件时间列过滤（格式看「取数」或那一列的全文），不加分区条件——分区和事件日期差几天
     没人证明过，加了会漏行。
   - 没有这一行，或写「目录没记录」：照「取数」做。拉链表按有效期取一个时点。
   「范围」和约束里的过滤（有效记录、删除注销、去重）写进条件，没写进去的在答案里说为什么。
3. 目录有这个指标时，用它的度量、聚合、过滤、时间窗、维度原样写，不自己再推一个口径；问题与指标定义有出入时说出来。
4. 提问者没给的输入——日期范围及边界（含不含当天、一周从哪天起）、哪个来源或分支、按哪一天的状态、手里的号是哪一种——写成 SQL 开头的
   参数注释 `-- 参数 <名> = <值>（假设：提问者没给）`，答案的「假设」里逐条列出，不要悄悄选一个。材料已经定了的（用哪个日期列）不是假设。
5. 行的唯一性：说出每张表一行是什么（「目录」的粒度、「怎么读」的一行是），关联后哪一侧放大。包里的「一行是」、注意或待确认问题说同一
   键会有多行、而题目要计数或求和时，按那条给的键去重（`COUNT(DISTINCT …)`，或子查询里 `ROW_NUMBER()` 取一行），引用那一条；
   只提醒"会偏大"不算处理。材料没给去重键就按第 4 步留占位。
6. 码值只用包里列出的值；写着「含义待确认」的值照实说含义未确认，不当成已确认的用。
7. LEFT JOIN 右表的条件写进 ON。写进 WHERE 会把它变成内连接，`check-sql` 查不出来。

**4. 材料没给的定义：留占位。**

目录和这张表的表语义都没给的定义（什么算 X、哪些码算 Y、一个类别怎么划），不挑一列或一组码代替。写一个占位，SQL 照样能解析：

```sql
SELECT COUNT(*) AS cnt
FROM demo_dwd.dwd_party_customer_info_df c
WHERE c.dt = '2024-01-31'
  AND c.gender_cd IN (/* 待确认：性别码除 F、M、U 外还有哪些值 */ 'F', 'M')
  AND /* 待确认：注销的客户算不算 */ 1 = 1
```

- 注释以 `待确认` 加冒号（`：` 或 `:`）开头，后面一句话写缺的是什么；`--` 行注释也算，写在字符串里不算。
- 写在 `<列> <比较符>` 或 `<列> IN (` 之后，占位归到那一列；跟某一列无关的写成 `AND /* 待确认：… */ 1 = 1`。
- 占位后的值只为让 SQL 能解析：那一列有码值就从中挑一个，没有就写 `'待确认'`；答案里说这个值不是定义。
- 这张表的「待确认问题」里正好有一条问的就是这件事：占位文字用一句话概括那条问题，后面写（<库.表> q<号>）。别的表上的问题不能当这张表的依据。
- 能定的部分照常写完；不因一处未定整题不答。

**5. `check-sql`。** SQL 存成文件（如 `query.sql`）后：

```bash
scope-lineage catalog check-sql <O> query.sql
```

- 错误：必须改。退出码 2：解析不通过或没有查询，按消息给的行、列改。
- 警告：逐条对照包，包也这样说就改，不然在答案里写一句为什么留着。改法：`missing_partition_filter` 补一个分区（只在快照表上报）
  或拉链有效期条件；`code_value_unknown` 换成消息列出的值；`fan_out_unaggregated` 先在子查询里按粒度聚合或去重；`join_not_recorded`
  换成第 2 步关联一节的列对。
- 提示不用改：`pending_definition` 是你的占位；`table_not_in_catalog`、`column_unchecked` 在答案里说这张表或这列目录没有覆盖。
- 改完再跑。最多跑三次（第一次加两次修改）；第三次还有错误或警告就停，原样写进答案。
- `check-sql` 只对照目录：没报不等于对。「取数」说只取一个分区的表，没报也只取一个。

**6. 记下占位。** SQL 里有占位时，在最后一次 `check-sql` 之后跑一次（改过占位文字就别再跑旧版）：

```bash
scope-lineage catalog pending add <P> --from-sql query.sql --question "<问题原文>"
```

退出码 1 表示 SQL 里没有占位，或有占位没写缺什么（补上文字再跑）。没有占位就跳过这一步。

**7. 答案按这个顺序写：**

1. **SQL**：`check-sql` 后的那一版。题目问的是是 / 否或会 / 不会时，SQL 前先用一句话直接回答。
2. **表和关联**：每张表一行是什么；关联列对及依据（关联一节的「同一标识 …」或「语料中见过」）；哪一侧放大、怎么处理的。
3. **条件和依据**：每个过滤、去重、日期列、指标口径一行，`<条件> — <表 · 节 / 规则 r? / 约束 id / 指标 id>`。
4. **假设**：第 3 步第 4 条的每个参数，取了什么值，换值改哪里。
5. **待确认（交目录负责人）**：每个占位缺什么、落在哪一列、引用的表待确认问题（没有写"无"）、是否已记入 `<P>`。
6. 留着的 `check-sql` 警告与理由；状态 `drafted`、证据与目录矛盾、含义待确认的码值按 `references/catalog-questions.md`
   「回答时带上什么」照实转述。

## 多轮问数：每题一个子代理，主对话只留简报

上下文有限，问题一个接一个来。每个问题的第 1–6 步交给一个新的子代理：给它问题原文、`<O>` `<S>` `<P>` 的路径和本文件路径，
要它照本文件做，按下面的格式交回简报（写 SQL 的题，简报就是第 7 步的内容；不写 SQL 的题，`SQL`、`关联`、`条件` 写"无"，`结论`
写直接答案）。主对话不跑 `search` / `context` / `check-sql`，不读取数包，把简报写成给提问者的答案。

简报不超过 5 KB；超了就把每条依据缩成出处（表 · 节、规则号、约束 id），不删任何一项：

```text
问题：<原文>
结论：<一句话直接答案>
SQL：<最终 SQL>
表：<库.表> — 一行是 <粒度>            （每张表一行）
关联：<A.列 = B.列> — <依据>；放大：<哪一侧，怎么处理 / 无>   （一张表时写"无"）
条件：<条件> — <依据>                  （每条一行）
假设：<参数> = <值>                    （每条一行）
待确认：<占位文字> — <列>；<表 q 号 / 无>；已记入 <P>
check-sql：错误 <n>，警告 <n>；留着的警告：<规则 — 理由 / 无>
```

追问上一题（"再按另一个维度分""换成上个月"）时，把上一题的简报和新问题一起交给新的子代理：它从简报出发，只对新碰到的表或列重跑
第 2 步，再做第 3–6 步。没有子代理可用时：每题做完在笔记里只留这份简报，之后不再引用取数包的输出；后面的问题要用同一张表，
重跑第 2 步，不回头翻之前的输出。
